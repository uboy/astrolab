# Качество и метрики

## Текущее состояние тестирования
- В проекте реализованы автоматизированные тесты для ключевых узлов: парсинг резюме, логика списания баланса и маршрутизация команд.
- Покрытие тестами сосредоточено на критических DS-компонентах (извлечение данных из неструктурированного текста).

## Производительность и узкие места
- **JSON-хранилище**: Использование `users.json` для MVP оправдано скоростью разработки, но при росте базы (>1000 пользователей) потребуется переход на СУБД.
- **Очередь Ollama**: Тяжелые запросы (Vision, длинные резюме) могут занимать до 30-60 секунд. Реализована визуальная индикация прогресса для удержания внимания пользователя.

## Безопасность и приватность
- Все персональные данные (резюме, профили) хранятся локально.
- Доступ к админ-панели ограничен по белому списку ID пользователей из конфигурации.
- Секреты (токены) вынесены в переменные окружения и не попадают в репозиторий.

## Известные ограничения
- Платежи реализованы в режиме симуляции (Sandbox) для демонстрации процесса.
- Точность LLM-вердиктов зависит от выбранной модели (рекомендуется Llama 3 8B).
